# Git 사용하기
- gitLab 이 원칙
- powershell보다는 gitbash 권장
- 깃 컨피그 두줄 진행
- 노트북(local,directory) <=> gitlab(remote, repository, origin)
- git switch 는 브랜치
- Changes: 수정한파일들
  Staged Changes: 여기 올라온 파일만 커밋가능
- Commit 컨벤션 : 커밋메세지 규칙
- Merge : 브랜치들을 하나로 합치는 과정
    - Merge Request
    - 소스브랜치: 내가 개발한 내용
    - 타겟브랜치: 병합될 최종 브랜치
    - delete source branch 통해 그때그때 삭제 체크
- 충돌
    - 동일한 파일의 동일한 부분을 다르게 수정했을때
    - 방지
        - 방지하기 위해선 다른사람의 코드를 건들지 않기
        - git pull 을 통해 자주 동기화
        - 작은 단위로 자주 commit
    - 해결
        - 둘 다 날리기
        - 내거만 남기기
        - 남거만 남기기
        - 둘다 살리기
    - 충돌 마커
        - 마커 위의 4가지 버튼 중 하나 클릭해서 해결 권장
    - 본질은 코드이해 하기
    - 충돌은 다른 코드를 이해할 수 있는 기회다
# Jira
- 개념
    - 왜 사용하는가?
        - 나: 내가 일주일간 할일 적고 하루에 뭘할지 기록
        - 팀원: 팀원의 개발상황,이슈를 확인가능
        - 팀단위: 팀단위 주차별, 매일 일정 관리가능
- 스프린트란?
    - 프로젝트 기간을 나눈 단위.
    - 권장은 월요일시작 일주일 단위 => 총 4번의 스프린트
    - 각 스프린트 기간에 계획한 일정 완수하는게 목표
- 이슈란?
    - 할 일
    - 이슈유형: 에픽,스토리,작업
    - 에픽: 큰 목표(회원가입기능구현)등 상위단계 이슈
    - 스토리: 사용자관점의 기능,요구사항(이메일로로그인, 입력란UI만들기 등)
    - 작업: 스토리실현을 위해 구체적으로 할일(개발자관점에서 할일)

# 오늘 친 코드
- npm create vite@latest frontend -- --template react-ts
    - 최신 Vite 프로젝트 생성 도구를 실행한다.
    - 저장소안에 frontend 라는 새 폴더를 만든다
    - React와 TypeScript가 적용된 기본 프로젝트를 생성합니다.
- ls frontend
    - frontend 폴더 안 파일확인
- cd frontend
- npm install
    - package.json에 적힌 React, Vite 등 필요한 라이브러리를 설치합니다. 이미 설치돼 있더라도 누락된 항목이 없는지 다시 맞춰 줍니다.
- npm run dev
    - Vite 개발 서버를 실행합니다.
- npm run build
    - React + TypeScript 코드를 실제 배포 가능한 파일로 변환하는 명령어입니다. Vite 프로젝트에서는 이 명령으로 프로덕션 빌드 오류가 없는지 확인합니다.
- ls
    - 현재 폴더에 dist생성된거확인
- git status
    - Git이 어떤 파일을 새 파일 또는 변경 파일로 인식하고 있는지 확인합니다.
- npm install phaser
    - Phaser 게임 라이브러리를 프론트 프로젝트에 설치합니다.
    package.json과 package-lock.json에 Phaser가 자동으로 등록됩니다.
    다른 팀원이 나중에 npm install을 실행하면 같은 라이브러리를 설치할 수 있게 됩니다.
- npm list phaser
    - 현재 프로젝트에 설치된 Phaser 버전을 확인합니다.
- npm run lint
    - 현재 React·TypeScript 코드가 ESLint 규칙을 위반하지 않는지 검사합니다. 오류 없이 끝나면 기본 프로젝트 코드가 정상이라는 뜻입니다.
- find src -maxdepth 2 -type f | sort
    - src 폴더 안에 현재 어떤 파일들이 있는지 확인합니다. 기존 파일을 확인한 뒤 Phaser 구조를 추가하기 위해 필요합니다.
- cat package.json
    - React, Vite, TypeScript, Phaser와 실행 명령어가 package.json에 제대로 등록됐는지 확인합니다.
- mkdir -p src/components/game src/game/config src/game/scenes
    - mkdir: 폴더를 생성합니다.
    -p: 중간 폴더가 없어도 함께 생성합니다.
    React 컴포넌트와 Phaser 설정·Scene을 서로 다른 위치에서 관리합니다.
- touch src/components/game/PhaserGame.tsx \
      src/game/config/gameConfig.ts \
      src/game/scenes/MainScene.ts
    - 내용이 비어 있는 파일 3개를 생성합니다.
    PhaserGame.tsx: React가 Phaser 게임을 생성하고 제거
    gameConfig.ts: Phaser 화면 크기와 Scene 설정
    MainScene.ts: 실제 Phaser 테스트 화면
- npm run lint
    - 방금 작성한 TypeScript 코드에 문법이나 ESLint 오류가 있는지 확인합니다.
